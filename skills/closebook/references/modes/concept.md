# Mode: conceptual understanding (概念理解)

**When to load:** the learner wants to *understand* a theory, mechanism, model or framework (science, economics, system architecture, philosophy of a method), rather than memorise or perform.

**Bias (never overrides `method-fit.md`):** Feynman + elaborative interrogation + self-explanation + **analogy testing**.

## What changes
1. **Feynman is the main retest** for core points: explain in plain words, outsider follow-ups, gap list, re-explain.
2. **Why / why-not questions** (elaborative) for each causal link. The first question on a core point is a why or what-if question ("what breaks if step 3 is removed?"), not "list what X does".
3. **Self-explanation** of a worked example when the learner is new to the topic (path B), before asking for a free explanation.
4. **Analogy testing:** ask the learner to propose an analogy, then ask where it breaks. This reveals which features they consider essential. "You said a cache is like a fridge; what does the fridge get wrong about ETags?"
5. **Transfer questions:** apply the concept to a new case with a known outcome. Predict-verify only if the outcome is checkable.
6. **Interaction:** mostly `free_text`/`plain_qa`. `diagram_fill` for structures and flows (fill or predict first). MCQ only with real-misconception distractors.

## What doesn't change
- Factual sub-parts (names, constants, formulas) are drilled with retrieval, without analogies.
- Contested parts of a theory (open debates) are scored on coherence, not correctness.

## Progress fields
Session `mode: "concept"`; `feynman` object per point; analogy proposals can go in the attempt `note`.
