我把“所有权”按学习顺序拆成 5 个点：

1. [核心 · 概念] 所有者与 move：把一个值交给另一个变量时发生了什么。讲解 → 小检查 → 预测代码能不能编译。今天 15 分钟只做这一个。
2. [核心 · 概念] 变量离开它的作用范围时，它拥有的值会怎样。讲解 → “为什么”追问。
3. [重要 · 概念] 整数赋值和文本赋值为什么表现不同（Copy 与 clone）。讲解 → 预测输出。
4. [核心 · 概念] 借用：不拿走所有权也能用一个值（& 和 &mut 的规则）。讲解 → 预测编译 → 用自己的话解释。
5. [重要 · 判断] 写函数时，是把所有权交出去，还是只借用。选择并说理由。

第 2 到 5 点先存着，留给以后的课。想改顺序或删减就直说，否则直接回答文末那道题。如果你连别的编程语言也没写过，也告诉我，我换更生活化的例子。

第 1 块：所有者与 move

先看 4 行 Rust（println!("{}", x) 的意思就是“打印 x”）：

  1  let a = String::from("hello");
  2  let b = a;
  3  println!("{}", b);
  4  println!("{}", a);

第 1 行在内存里创建了一段文本 "hello"，由变量 a 负责管理它。a 就叫这段文本的“所有者”（owner）。Rust 规定：一个值同一时刻只能有一个所有者。

第 2 行的 let b = a; 不是复制一份文本，而是把所有权交给 b，这叫 move（移动）。从这一行起，a 就作废了。

所以第 3 行没问题，会打印 hello。第 4 行会让编译器直接报错，程序根本跑不起来，因为 Rust 在编译时就会拦下“使用已经被 move 走的变量”。

一句话规则：把 String 这类值赋给另一个变量，所有权就搬过去了，旧变量不能再用。

容易混淆的地方：如果你写过 Python 或 JavaScript，在那里写 b = a 之后，a 和 b 都还能用。但在 Rust 里，上面这段不行。

这一点是在讲一个机制，所以我让你预测代码能不能编译，而不是复述定义，这样更能看出你是不是真懂了。
